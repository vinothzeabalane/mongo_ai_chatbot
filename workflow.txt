Query Object (core/parser.py → Query)
  field        description
  operation    list | metric | lowest | highest | average | count | chart | all_values
  metric       e.g. SBL_TOTAL, OVERALL_TOTAL, MAINFW_CORESIGHT_INIT
  hostname     e.g. rc136-031-19-s3
  bootType     EB0 | SPI
  sku          e.g. 60TB
  date_from    YYYY-MM-DD
  date_to      YYYY-MM-DD
  group_by     hostname | bootType | sku | date
  limit        1–5000 (default 100, MAX_LIMIT=5000; "all/every/everything" → MAX_LIMIT)
  value_field  "min" | "max" — which timing column to sort/aggregate on
                 fastest/slowest  → max   (sort on max_seconds)
                 lowest minimum   → min   (sort on min_seconds)
                 highest/average  → max

  "all_values" operation:
  - Triggered when the question contains "all" + values/metrics/data/columns/fields/everything.
  - metric unset  → build_metric_pipeline() projects the full nested data{} subdocument;
                    ui/formatter.py records_to_rows() explodes it into one row per metric.
  - metric set    → same as "metric" operation but limit defaults to MAX_LIMIT.

Date Extraction (core/parser.py → extract_dates)
  Explicit dates    "2026-08-01" / "2026/08/01", or two dates → (date_from, date_to)
  Relative days      today | yesterday | tomorrow           → single-day range
  Relative weeks     this week | last week                  → Mon–Sun range
  Relative months    this month | last month | previous month → calendar-month range
  Month + year       e.g. "during July 2026"                → full calendar-month range
  All computed from datetime.date.today() at parse time (no timezone handling).

  Routing note: is_simple_dashboard_question() treats "between", "during", "last/this week",
  "last/this/previous month" as complex-language triggers UNLESS extract_dates() can already
  resolve them deterministically, in which case the question still stays on the regex parser.


Security (core/query_validator.py)
- LLM response scanned for forbidden Mongo operators before processing:
  $where, $lookup, $function, $accumulator, $out, $merge, $graphLookup, mapreduce
- metric must be in KNOWN_METRICS or request is rejected with a clear error
- value_field must be "min" or "max" — anything else is silently cleared to null
- operation must be in ALLOWED_OPERATIONS — anything else defaults to "list"


Interaction Logging (core/interaction_logger.py)
- log_interaction(payload) appends a UTC-timestamped JSON record to QUERY_LOG_PATH.
- Sensitive data masked before writing: IP addresses and hostnames (rc/lm-* patterns).
- Thread-safe: uses _WRITE_LOCK.
- File rotation: when log exceeds LOG_MAX_BYTES it is renamed to .1, .1→.2, …, oldest dropped.
- Logging disabled by setting ENABLE_QUERY_LOGGING=0.
- Three event types logged by app.py:
    query_success  — dashboard query returned results
    query_offtopic — question routed to LLM plain-text fallback
    query_error    — unhandled exception (includes error type + message)

Log Analysis (scripts/summarize_logs.py)
- CLI: python scripts/summarize_logs.py [--path <file>] [--top <N>]
- Reads JSONL log and reports: total records, failure count, off-topic count,
  top N failed questions, top N off-topic questions, suspected misroutes.


Routing Decision (is_dashboard_question)
- Any UPPER_CASE_WITH_UNDERSCORES token → dashboard  (e.g. MAINFW_CORESIGHT_INIT)
- Any keyword from DASHBOARD_KEYWORDS       → dashboard  (host, metric, boot, spi …)
- Anything else                             → LLM fallback

Notes
- parser.py uses deterministic regex/keyword rules; LLM is only used for off-topic questions.
- Metrics live in nested Mongo fields: data.<METRIC_NAME>.min / .max
- config.py holds MongoDB, Ollama, and interaction-logging settings (env-var overridable).
- tests/test_smoke.py is the automated regression suite, run with: python -m pytest tests/test_smoke.py -v
- tests/test_concurrency.py covers multi-user access, run with: python -m pytest tests/test_concurrency.py -v


Concurrency / Multi-User Access
- Streamlit runs each browser session in its own thread within the same server process,
  so all sessions share one Python process and one set of module-level globals.
- core/mongo.py: single module-level MongoClient (thread-safe, pools its own connections)
  shared by every session. First-time creation is guarded by _INIT_LOCK (double-checked
  locking) so two sessions hitting a cold start at the same instant can't create duplicate
  clients.
- st.session_state (question_input, result_ready) is isolated per browser session by Streamlit.
- execute_cached() in app.py uses @st.cache_data(ttl=60) keyed only by query params — safely
  shared across users since results don't depend on user identity.
- core/interaction_logger.py serializes log writes/rotation with a threading.Lock (_WRITE_LOCK)
  so concurrent writes never interleave or corrupt the JSONL file.
- tests/test_concurrency.py verifies: (1) concurrent get_collection() calls return the same
  MongoClient singleton, (2) concurrent execute() calls across mixed operations complete
  without error, (3) concurrent log_interaction() writes produce valid, non-corrupted JSONL.


config.py — Interaction Logging Settings
  ENABLE_QUERY_LOGGING   1/0          toggle logging on/off (default 1)
  QUERY_LOG_PATH         path         JSONL log file (default logs/chatbot_interactions.jsonl)
  MASK_LOG_SENSITIVE     1/0          mask IPs and hostnames in logs (default 1)
  ADMIN_LOG_TAIL_LINES   int          lines shown in Admin log viewer (default 100)
  LOG_MAX_BYTES          int (bytes)  rotate log file when it exceeds this size (default 5 MB)
  LOG_BACKUP_COUNT       int          number of rotated backup files kept (default 5)


UI / app.py Features
- Query result caching: @st.cache_data(ttl=60) on execute_cached() to reduce MongoDB load.
- Context pills display active filters: 📊 Metric, 🖥 Host, 🔧 Boot Type, 💾 SKU, 📅 Date Range.
- Charts shown automatically for operation=="chart"; collapsible expander for multi-row metrics.
- Results table label shows row count.
- Admin log viewer (sidebar): shows logged-event count, success/failure split, recent entries.
