Query Object (core/parser.py → Query)
  field        description
  operation    list | metric | lowest | highest | average | count | chart
  metric       e.g. SBL_TOTAL, OVERALL_TOTAL, MAINFW_CORESIGHT_INIT
  hostname     e.g. rc136-031-19-s3
  bootType     EB0 | SPI
  sku          e.g. 60TB
  date_from    YYYY-MM-DD
  date_to      YYYY-MM-DD
  group_by     hostname | bootType | sku | date
  limit        1–500 (default 100)
  value_field  "min" | "max" — which timing column to sort/aggregate on
                 fastest/slowest  → max   (sort on max_seconds)
                 lowest minimum   → min   (sort on min_seconds)
                 highest/average  → max


Security (core/query_validator.py)
- LLM response scanned for forbidden Mongo operators before processing:
  $where, $lookup, $function, $accumulator, $out, $merge, $graphLookup, mapreduce
- metric must be in KNOWN_METRICS or request is rejected with a clear error
- value_field must be "min" or "max" — anything else is silently cleared to null
- operation must be in ALLOWED_OPERATIONS — anything else defaults to "list"


Routing Decision (is_dashboard_question)
- Any UPPER_CASE_WITH_UNDERSCORES token → dashboard  (e.g. MAINFW_CORESIGHT_INIT)
- Any keyword from DASHBOARD_KEYWORDS       → dashboard  (host, metric, boot, spi …)
- Anything else                             → LLM fallback

Notes
- parser.py uses deterministic regex/keyword rules; LLM is only used for off-topic questions.
- Metrics live in nested Mongo fields: data.<METRIC_NAME>.min / .max
- config.py holds MongoDB and Ollama connection settings (env-var overridable).
- tests/test_smoke.py is the automated regression suite, run with: python -m pytest tests/test_smoke.py -v
